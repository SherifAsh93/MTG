Five confirmed open defects

  1. High — Storage errors are followed by success messages
    Four failing cases: client creation, project creation, record saving and default prices.
  2. High — Two-tab editing loses an earlier change
    A stale second tab overwrites the first tab’s newly created client.
  3. Medium — Tablet App library overflows horizontally
    781px content in a 768px viewport; the last category button crosses the edge.
  4. Medium — Malformed stored state crashes startup
    An invalid project shape results in a blank app without a recovery screen.
  5. Medium — Unknown schema resets the active workspace silently
    A raw backup existed in the test, but no version/recovery message was shown.

Recommended priority: address failed-save feedback and lost updates first, then tablet layout and stored-data recovery. Rerun the audit after fixes. Backend work awaits an approved remote/cloud environment.

What was exercised

  • All 10 starting points and generic record create/read/edit/delete for all 13 catalog modules.
  • Client/profile/project management, search, selection, archiving/reactivation and deletion.
  • Entities/fields, supported field types, pages, ordering, visibility, dependent rules, templates and snapshot previews.
  • Pricing/defaults/discounts, quote-export payload, branding and PNG/JPEG/WebP upload success/rejection.
  • Reloads, injected storage failures, two-tab editing, malformed/unsupported stored state and five viewport sizes.
  • Literal rendering of HTML-like input and limited keyboard/dialog operations. Full security, browser/device and accessibility certification are not claimed.
